# Как устроен tray-idle-inhibitor и почему именно так

Документ для тех, кто захочет доработать программу: здесь собраны решения,
которые пришлось принять по ходу, и причины, по которым отвергнуты более
простые варианты. Если коротко — приложение маленькое, но у него два разных
потребителя инхибитора и три источника цвета, и почти вся сложность растёт
именно отсюда.

## Для кого

Целевая среда — Wayland-сессия на wlroots (labwc, sway) с панелью LXQt или
Waybar и системой на systemd. Программа не привязана к LXQt: трей работает
через StatusNotifier, а цвет иконки умеет брать из LXQt, Waybar или swaybar.
X11 не поддерживается — там нет `zwp_idle_inhibit_manager_v1`.

## Почему инхибиторов два

«Не дать системе уснуть» на Wayland — это два независимых механизма, и ни один
не заменяет другой:

1. **Композитор (wayland).** `zwp_idle_inhibit_manager_v1` создаёт инхибитор,
   привязанный к поверхности. Его видят wlroots и всё, что полагается на
   композитор при принятии решения об idle.
2. **logind (D-Bus).** `org.freedesktop.login1.Manager.Inhibit("idle", …,
   "block")` выставляет `idle` в свойстве `BlockInhibited`. Именно это свойство
   читают `swayidle` и `systemd-inhibit`; wayland-поверхность для них ничего
   не значит.

Если держать только wayland-инхибитор, `swayidle` продолжит считать, что
блокировок нет. Если держать только logind — композитор не узнает, что
пользователь просил не гасить экран. Поэтому `Hold` в `src/main.rs` поднимает и
снимает оба механизма одной операцией; частичный успех допустим и логируется.

## Почему своя поверхность 1×1

wlroots учитывает инхибитор только для поверхности, у которой привязан буфер и
которая закоммичена. Пустая поверхность без буфера молча пропускается — именно
поэтому «инхибитор без окна» не работает, если сделан наивно.

Waybar вешает инхибитор на поверхность бара: она видимая, буфер у неё есть.
Нам бар не нужен, поэтому создаётся собственная невидимая поверхность:

- `wl_shm` + `memfd` на 4 байта (1×1, `Argb8888`, прозрачный пиксель);
- `create_pool → create_buffer → attach → commit → create_inhibitor`;
- обязательный `roundtrip` после создания: без обработки событий композитор
  может не увидеть привязанный буфер и проигнорировать инхибитор.

Порядок запросов зафиксирован в README и проверялся по `WAYLAND_DEBUG=1`.

## Почему fd у logind хранится, а соединение — нет

`Inhibit` возвращает файловый дескриптор; блокировка живёт ровно столько,
сколько он открыт. Поэтому `LogindInhibitor` хранит только `OwnedFd`, а
D-Bus-соединение используется на время вызова и закрывается. Снимать
блокировку отдельным методом не нужно: `Drop` закрывает fd, и ядро само
убирает `idle` из `BlockInhibited`. Это же свойство даёт устойчивость к
падению процесса — протухших блокировок не остаётся.

## Цвет иконки: почему из темы, а не из константы

Иконка 22×22 рисуется программно, внешняя тема иконок не требуется. Цвет
берётся из темы панели, потому что панель уже рисует этим цветом свои подписи —
значит он читаем на её фоне. Приоритет в `src/theme.rs`:

1. `color` в правиле `Plugin > QToolButton` (кнопки плагинов, включая трей);
2. `color` в `LXQtPanel { … }`;
3. `color` в `LXQtPanel #BackgroundWidget { … }`;
4. `window_text_color` из палитры темы;
5. фон панели и чёрный/белый по яркости (порог 0.4);
6. белый, если фон не найден.

Токены `palette(...)` резолвятся из палитры той же темы. Тема берётся из
`~/.config/lxqt/lxqt.conf` или из `[color] theme`, палитра — из
`$XDG_DATA_DIRS/lxqt/palettes/<Имя>`. Фон определяется у реально запущенной
панели: qss LXQt, `panel.conf`, `style.css` Waybar или конфиг swaybar.

Режимы `color.mode` дают выход, если цепочка не подходит: `auto` считает только
контраст к фону, `fixed` берёт заданный цвет. Это осознанный компромисс:
универсально «правильного» цвета нет, а угадывать тему, изменённую через
qt5ct, невозможно.

## Конфигурация: два слоя и мягкие отказы

Пути строятся по XDG:

- системный файл — первый существующий из `$XDG_CONFIG_DIRS`
  (`/etc/xdg/tray-idle-inhibitor/config.toml` по умолчанию);
- пользовательский — `$XDG_CONFIG_HOME/tray-idle-inhibitor/config.toml`
  (`~/.config/...`).

Пользовательский файл переопределяет только указанные ключи; секция `[color]`
сливается по ключам. Правила отказа выбраны так, чтобы программа никогда не
мешала работать:

- неизвестный ключ или неверный тип — файл отбрасывается целиком, причина в
  stderr, остаются системный слой и значения по умолчанию;
- неверное значение отдельного ключа (`mode = "rainbow"`, `interval_secs = 0`)
  — ключ игнорируется с предупреждением, файл продолжает действовать;
- конфиг читается один раз: после правки нужен перезапуск.

Флаги командной строки сильнее конфига. Так проще временно переопределить
поведение, не редактируя файл.

## Один экземпляр

Две иконки в трее и два набора инхибиторов не нужны. Защита — `flock` на
`$XDG_RUNTIME_DIR/tray-idle-inhibitor.lock` (резерв — файл с uid в `/tmp`).
Блокировку снимает ядро при завершении процесса, поэтому «протухший» lock не
мешает следующему запуску. Если файл блокировки недоступен (каталога нет, нет
прав), программа пишет причину и продолжает работу без защиты — отказ
запуститься в этом случае был бы хуже дубля.

## Медиа и ручное управление

`--auto` раз в `interval_secs` (по умолчанию 5) спрашивает
`playerctl --all-players status`. Своя реализация MPRIS через zbus потребовала
бы подписок на появление плееров и больше кода; `playerctl` — одна команда,
которая уже стоит у большинства пользователей. Если его нет, причина один раз
пишется в stderr, а программа продолжает работать.

Правило включения: `manual || (playing && !suppressed)`. Ручное включение
сильнее медиа. Ручное выключение при играющем медиа не просто снимает флаг:
оно подавляет `auto`, пока медиа не остановится, иначе следующий тик вернул бы
инхибитор и клик выглядел бы сломанным. Клик считается по фактическому
состоянию (`toggle_state`), а не по флагу `manual`: при активном `auto` флаг
может быть `false`, и наивное `!manual` включало бы инхибитор вместо
выключения.

## Что осталось за рамками

- **X11 и не-wlroots композиторы.** Другой протокол инхибитора — другая
  программа, а не настройка.
- **Прямая работа с MPRIS без `playerctl`.** Возможна, но это заметный объём
  кода ради отказа от одной утилиты.
- **Горячие клавиши.** Их естественное место — настройки композитора или
  панели; в трее достаточно клика и меню.
- **Установка иконок в hicolor.** Иконки генерируются в рантайме, тема не
  нужна; `Icon=coffee` в `.desktop` относится только к записи меню.

## Куда расширять

- Новый источник цвета — `src/theme.rs`: добавить правило в цепочку и тест на
  разбор.
- Новый ключ конфига — `src/config.rs`: поле в `Patch`, слияние в `apply`,
  строка в таблицу README и в пример `config.toml`.
- Новый способ инхибитора — ещё одно поле в `Hold` и ветка в `acquire`;
  правило «частичный успех допустим» уже задано.
- Новый режим поведения — `want_inhibit` и `toggle_state` в `src/main.rs`;
  они чистые и покрыты тестами, менять цикл событий не нужно.
