# tray-idle-inhibitor

Апплет системного трея (StatusNotifierItem) для labwc / LXQt на Wayland: не даёт
системе уснуть, как модуль `idle_inhibitor` в Waybar, но без бара.

| Состояние | Иконка |
|---|---|
| инхибитор включён | чашка бодрящего напитка |
| сон разрешён | луна с «z» |
| включено автоматически (медиа) | та же чашка |

ЛКМ по иконке — включить/выключить. ПКМ — меню (статус, переключить, выход).

Документация, `--help` и меню трея — на русском языке.

## Как держится инхибитор

Одновременно в двух местах, чтобы его видели и композитор, и logind:

1. **wayland** — своя поверхность с прозрачным буфером 1×1 (`memfd`) и
   `zwp_idle_inhibit_manager_v1.create_inhibitor`.
   wlroots учитывает инхибитор только для поверхности с привязанным буфером:
   пустую поверхность без буфера он пропускает.
2. **logind** — `org.freedesktop.login1.Manager.Inhibit("idle", …, "block")`.
   Блокировка живёт, пока открыт файловый дескриптор из ответа D-Bus.
   Именно этот инхибитор виден в `systemd-inhibit --list` и в `BlockInhibited`.

Оба поднимаются и снимаются одной операцией (`Hold` в `src/main.rs`), поэтому
иконка и реальное состояние не расходятся.

## Медиа (как в GNOME Caffeine)

`--auto` опрашивает MPRIS через `playerctl --all-players status` раз в `-i` секунд
и включает инхибитор, пока что-то играет: `want = manual || (auto && playing && !suppressed)`.

Ручное включение работает независимо от медиа. Ручное выключение приостанавливает
`auto`, пока медиа не остановится: на паузе или после конца воспроизведения
подавление снимается, и когда медиа заиграет снова, инхибитор поднимется сам.
Если `playerctl` не установлен или не запускается, причина один раз пишется
в stderr, а `--auto` продолжает работать без медиа.

## Опции

```
    --auto             включать инхибитор при воспроизведении медиа (MPRIS)
    --start-on         включить инхибитор при старте
-i, --interval <СЕК>   как часто проверять медиа и цвет панели (по умолчанию 5)
    --dump-icons       сохранить иконки в текущий каталог и выйти
-h, --help             справка
-V, --version          версия программы
```

Второй экземпляр не запускается. Программа берёт `flock` на
`$XDG_RUNTIME_DIR/tray-idle-inhibitor.lock` (без `XDG_RUNTIME_DIR` —
`/tmp/tray-idle-inhibitor-<uid>.lock`); если блокировка занята, печатается
`уже запущен (pid N)` и процесс выходит с кодом 0. Блокировку снимает ядро при
завершении процесса, поэтому протухший lock-файл не блокирует следующий запуск.
Проверка не зависит от того, из какого пути запущен бинарник. Если файл
блокировки недоступен (каталог не существует или не пишется), программа
предупреждает в stderr и продолжает работу без защиты от дублей — молча
отказываться запуститься хуже.

Флаги командной строки сильнее конфига: `--auto` и `--start-on` включают
соответствующую настройку, `-i` перекрывает `interval_secs`. `start_on` и `auto`
совместимы: с обоими инхибитор держится с запуска, а медиа лишь не даёт ему
отпуститься, пока что-то играет.

## Конфигурация

Два файла TOML, оба необязательные:

1. `/etc/xdg/tray-idle-inhibitor/config.toml` — системные значения по умолчанию
   (точнее: первый существующий файл из `XDG_CONFIG_DIRS`, а не первый каталог
   переменной);
2. `~/.config/tray-idle-inhibitor/config.toml` — пользовательский
   (`XDG_CONFIG_HOME`, если задан). Достаточно указать только изменяемые ключи:
   остальные наследуются из системного файла, вложенная секция `[color]`
   сливается по ключам.

`/etc/tray-idle-inhibitor/config` не используется: по XDG Base Directory
конфиги приложения кладутся в `$XDG_CONFIG_DIRS/<приложение>/`, иначе пакетные
менеджеры и `~/.config` перестают быть предсказуемыми.

Ключи:

| Ключ | По умолчанию | Смысл |
|------|--------------|-------|
| `auto` | `false` | То же, что `--auto`: включать инхибитор, пока играет медиа. |
| `start_on` | `false` | То же, что `--start-on`: держать инхибитор с запуска. |
| `interval_secs` | `5` | Период проверки медиа и перечитывания цвета, `>= 1`. |
| `color.mode` | `"theme"` | `theme` — цвет шрифта темы панели (иначе по контрасту), `auto` — только по контрасту к фону, `fixed` — цвет `fg`. |
| `color.theme` | — | Имя темы LXQt, из которой брать цвет, вместо активной из `lxqt.conf`. Позволяет не зависеть от темы панели и от `lxqt-panel`. |
| `color.fg` | `"#ffffff"` | Цвет иконки для `mode = "fixed"`, формат `#rrggbb`. |

Пример с комментариями — файл `config.toml` в репозитории. Неизвестный ключ или
неверный тип отбрасывает файл целиком (в stderr пишется причина), программа
продолжает работу на остальных слоях и значениях по умолчанию. Неверное
значение отдельного ключа (`mode = "rainbow"`, `fg = "white"`,
`interval_secs = 0`) не отбрасывает файл: ключ игнорируется с предупреждением.

Конфиг читается один раз при запуске — после правки перезапустите программу.

## Цвет иконки

Индикатор рисуется
**цветом шрифта активной темы LXQt** — панель рисует им свои подписи, значит он
читаем на её фоне. Приоритет источников:

1. `color` в правиле `Plugin > QToolButton` (цвет текста кнопок плагинов — трея);
2. `color` в `LXQtPanel { … }`;
3. `color` в `LXQtPanel #BackgroundWidget { … }`;
4. палитра темы, `window_text_color`;
5. если шрифт не определён — чёрный/белый по яркости фона (порог 0.4);
6. нет фона — белый.

Токены `palette(...)` в qss резолвятся из палитры той же темы. Тема берётся из
`~/.config/lxqt/lxqt.conf` (`[General] theme=`) или из `[color] theme` конфига,
палитра — из `<XDG_DATA_DIRS>/lxqt/palettes/<Имя>` (регистронезависимо).

`[color] mode` меняет поведение: `theme` — цепочка выше, `auto` — только
чёрный/белый по фону панели (тема не читается), `fixed` — ровно `color.fg`.
Последние два режима полностью снимают зависимость от темы панели.

### Тема `system` — почему цвет верный

В теме `system` (`/usr/share/lxqt/themes/system/lxqt-panel.qss`) нет правил
`Plugin > QToolButton`, `LXQtPanel` и `color` у `#BackgroundWidget`, а палитры
`lxqt/palettes/system` в системе нет вообще. Поэтому цепочка «цвет шрифта темы»
не находит ничего, и цвет берётся резервным путём: фон `palette(window)` из
`~/.config/lxqt/lxqt.conf` (`#efefef`) → тёмный индикатор `#181818`,
контраст 15.4:1. Проверено запуском с подменённым `XDG_CONFIG_HOME`
(`theme=system`), иконки — `--dump-icons`.

Отсюда следствие для остальных тем: цвет корректен, пока верно определён либо
цвет шрифта темы, либо фон панели. Если тема задаёт светлый текст для тёмных
кнопок (`Plugin > QToolButton { color: … }`), берётся он — контраст к фону
панели при этом не пересчитывается. Если панель красит свои кнопки через
qt5ct/KDE-схему мимо `lxqt.conf`, наши источники остаются прежними: это
известное ограничение, лечится `[color] mode = "fixed"` или `auto`.

Фон панели определяется у **реально запущенной** панели (`lxqt-panel` или Waybar;
`XDG_CURRENT_DESKTOP` может описывать сессию, а не панель):

* LXQt: qss темы `#BackgroundWidget` → `background-color` из `panel.conf` →
  палитра `window_color`;
* Waybar: `style.css` (`window#waybar`, `window.background`, `*`);
* swaybar: `background` из `~/.config/sway/bar`.

Цвет перечитывается на каждом такте `-i`, поэтому смена темы подхватывается
без перезапуска.

```bash
./target/release/tray-idle-inhibitor --dump-icons
# inhibit.png / sleep.png — цвет #313639 на панели #f0f0f0, контраст 10.7:1
```

Проверено на 12 темах LXQt (light, dark, graphite, Clearlooks, system, silver,
Valendas, Arch-Colors, ambiance, frost, kvantum, Leech) — контраст от 9.8:1
до 19.0:1.

## Требования

- Rust 1.87+ (`rust-version` в `Cargo.toml`), для сборки — только toolchain.
- Wayland-сессия с протоколом `zwp_idle_inhibit_manager_v1` (wlroots: labwc,
  sway, Hyprland и т.п.).
- StatusNotifier-хост в панели: `lxqt-panel`, `waybar` или другой трей.
- logind на системном D-Bus (`org.freedesktop.login1`), чтобы инхибитор был
  виден `systemctl`/`swayidle` в `BlockInhibited`.
- `playerctl` — только для `--auto`; без него программа работает, но медиа
  не учитывает (причина один раз пишется в stderr).

Если инхибитор не удаётся поднять хотя бы одним из способов, программа
пишет причину в stderr и продолжает работу: один доступный путь уже полезен.

## Сборка

```bash
cargo build --release
```

## Установка

```bash
sudo install -Dm755 target/release/tray-idle-inhibitor /usr/local/bin/tray-idle-inhibitor
sudo install -Dm644 config.toml /etc/xdg/tray-idle-inhibitor/config.toml
sudo install -Dm644 tray-idle-inhibitor.desktop /usr/local/share/applications/
```

Без установки можно запускать прямо из `target/release/`.

## Запуск

```bash
tray-idle-inhibitor --auto
tray-idle-inhibitor --version
```

Автозапуск — `~/.config/autostart/tray-idle-inhibitor.desktop`. Скопируйте
файл из репозитория или создайте свой:

```ini
[Desktop Entry]
Type=Application
Name=Tray Idle Inhibitor
Comment=Idle inhibitor in the system tray
Exec=/usr/local/bin/tray-idle-inhibitor --auto
Icon=coffee
Terminal=false
X-LXQt-Need-Tray=true
```

## Устройство кода

* `src/wayland.rs` — поверхность + буфер + `zwp_idle_inhibitor_v1`.
* `src/logind.rs` — `Inhibit("idle")` на системном D-Bus, удержание fd.
* `src/main.rs` — трей `ksni`, события (клик/синхронизация/выход), `Hold`.
* `src/config.rs` — чтение и слияние `config.toml` (XDG), проверка значений.
* `src/icons.rs` — иконки 22×22 ARGB32 и PNG-кодировщик.
* `src/theme.rs` — цвет иконки по теме, фону и цвету шрифта панели.
* `src/media.rs` — проверка MPRIS через `playerctl`.

## Что проверено

* `cargo test` — 16 тестов (цвет, контраст, разбор qss/палитры/иконок, слияние конфига, единственный экземпляр и отказ при недоступном lock-файле, правило «ручное сильнее auto»).
* Создание wayland-инхибитора: по `WAYLAND_DEBUG=1` запросы идут в правильном
  порядке — `create_surface → create_pool(4) → create_buffer(1×1, Argb8888) →
  attach → commit → create_inhibitor`.
* logind-инхибитор: при включённом состоянии `systemd-inhibit --list` показывает
  строку `tray-idle-inhibitor … idle … block`, после выключения — не показывает.

## Ограничения, найденные на практике

* `swayidle` 1.9.1 на этой машине не может прочитать свойство `BlockInhibited`
  (в логе `Failed to parse get BlockInhibited property: Invalid argument`),
  поэтому на logind-инхибитор он не реагирует и не печатает
  `Not enabling timeouts: idle inhibitor found`. На системах с рабочим
  `BlockInhibited` этот путь должен срабатывать.
* Подавление таймаутов `swayidle` через wayland-инхибитор достоверно замерить
  в интерактивной сессии не удалось: базовый прогон без инхибитора тоже
  не срабатывал, пока в сессии была активность ввода.
